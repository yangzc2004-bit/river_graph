# 训练数据与模型规模核对（2026-09-11）

本报告根据本地数据文件、mask 文件和当前模型代码核对；没有启动训练、重新下载数据或改动训练逻辑。模型扩展规模仅为参数计数，不是 GPU 实测。

## 主要结论

- 当前主数据集使用筛选后的全部 571 个节点，不是早期 50 站点 smoke 数据集。
- v04 数据集含 33,048 个有效 DOC 站点月标签；其中 570 个站点有标签，月份范围为 1972-04 至 2026-07，共 652 个月。571×652 的网格并不代表全部都有答案，标签覆盖率仅 8.88%。
- E2b 有 25,771 个训练标签、4,093 个验证标签、2,547 个测试标签和 637 个仅作上下文的标签。训练标签时间为 1972-04 至 2016-02，验证为 2016-03 至 2020-12，测试和上下文为 2021-01 至 2026-07。
- 当前 H2X 默认配置为 64 维、2 层，共 23,461 个可训练参数。当前 Python 环境为 CPU 版 PyTorch，CUDA 不可用；训练入口尚未配置 GPU 数据迁移。
- 扩容前需要优先处理站点类型：571 个节点中只有 435 个标为 ST（河流），还混有地下水井、湖泊/水库、陆地、降水采集等类型。不能把它们不加区分地作为相同河道节点。

| 层次 | 核对结果 |

| 目录内普通河流 ST 站点 | 2,975 |

目录记录只是可用性信息，并不等于已经下载所有站点的浓度值。目录计数与 WQP 实测数据更新和筛选口径不同，不能直接相除作为下载完成率。当前逐站缓存集合与图站点集合完全一致；47,517 条记录按月聚合后恰为数据集中的 33,048 个标签。目录存在少量同站多条记录和一条完全重复记录，后续扩容需规范去重。

## 同一区域内可扩展的普通河流 ST 站点

保持记录跨度至少 2 年，仅放宽每站最低观测数：

| 最低记录数 | 候选普通河流站点数 | 候选行目录观测计数 |
|---|---:|---:|
| 1 | 836 | 41,313 |
| 5 | 778 | 41,132 |
| 10 | 653 | 40,258 |
| 20 | 435 | 37,245 |

这些是候选数量，不是承诺可用的最终训练数量。需要下载观测、质控、按月聚合和河网匹配。从 >=20 条放宽至 >=10 条，站点数从 435 增至 653，但目录观测计数仅从 37,245 增至 40,258（约 8.1%）；不能把站点增加 50% 误认为标签也增加 50%。

现有缓存还包含未接入模型的 pH 和电导率：按当前提取器分别有 216,333 和 254,044 条记录（全部缓存时间范围）。这些可以增加输入信息，但不会增加 DOC 答案数量，且使用前要确认单位、可用时间与任务设定。

更大幅扩展可考虑其他流域，以及 WQP 中 USGS 之外的 EPA/WQX 等来源；仍需统一 DOC 定义、样品介质、单位、检出限和重复记录处理，并预留整流域测试。

## 模型扩展的参数计数

下面按当前 H2X 空间模块加单层、同宽度 GRU 估算；保留相同维度的输出头，实际 H3 实现不同会改变计数。

| 隐藏维度 | 空间层数 | 空间模块参数 | 加单层 GRU 后参数 | FP32 Adam 常驻参数相关内存（MB） |
|---|---:|---:|---:|---:|
| 64 | 2 | 23,461 | 48,421 | 0.77 |
| 128 | 2 | 69,605 | 168,677 | 2.70 |
| 256 | 3 | 433,255 | 828,007 | 13.25 |
| 512 | 3 | 1,650,791 | 3,226,727 | 51.63 |
| 1024 | 3 | 6,445,159 | 12,742,759 | 203.88 |

参数相关内存按 FP32 权重 4 字节、梯度 4 字节、Adam 两组状态 8 字节，共 16 字节/参数估算，不含激活、图结构、输入、算子临时内存及分配器开销。1 亿参数约 1.6 GB、10 亿参数约 16 GB仅指这些常驻状态，不能用该数直接推断完整训练能否放入显存。GNN+GRU 的节点数、边数和时间窗口也会影响显存，需运行代表性训练步骤测峰值与耗时。

在合理的时间窗口和批处理下，单卡 24GB 可作为当前规模及上述小到中等模型的首轮试租配置；这是工程估计，非本机 GPU 实测。若需要更大图或更长时间窗口，再依据实测比较 80GB 单卡。多卡优先考虑并行跑独立种子和实验；单个模型分布式训练需单独实现，多卡显存不会自动合并。当前 CPU 小步逐月训练代码也需要适配 GPU 和批处理，不能直接保证换卡后的加速倍数。

## 建议顺序

1. 明确河流站点纳入规则并完成数据清理，重新构图和划分。
2. 完成可复现训练流程；将普通河流候选站点扩到 653/778 规模并验证收益。
3. 完成 GPU 与时间窗口训练适配，先做 24GB 单卡短时基准。
4. 比较约 5 万、17 万、83 万参数模型的多种子验证表现，同时记录显存和时间。
5. 只有数据扩展与模型扩展有稳定收益时，才租更多资源做全量实验。
