## 1. B0：修生态分组取列错误

- **问题**：`src/river_graph/models/gcn.py` 的 `env_groups` 分支里，`keep` 存的是**原始列号**，`pos` 用它做字典键，随后 `env_cols` 又把这些原始列号当成**重新索引后的位置**使用。子集时取错列；默认全特征（`env_groups=None`）走 `range(13)`，`pos` 恰好退化为恒等，因此 H2X 默认路径不受影响。
- **先做**：修代码 + 加单元测试（构造已知列值的合成 regime 矩阵，断言选中的列确实是指定分组）。**零训练。**
- **再定**：标记 `H2X_{hydro,landcover,climate,soil_topo}_river` 的 16 行历史指标为「机制结论失效」，仅在历史描述中使用（本轮已在 manifest 与报告中标注）。
- **最小实验**：修好后每组生态分组重跑 8 key mask × 1 训练种子 = 32 次运行；若要五种子则 160 次。
- **要求**：科学结论必须等待正确的新实验，不能由修好的代码回溯宣称旧结果有效。

## 2. B1：明确河流纳入规则，建立 ST 核心版本

- **问题**：571 个节点中只有 435 个标为 ST（河流），其余混有地下水井（GW/GW-CR）、湖泊水库（LK）、陆地（LA）、降水采集（FA-*）等。混合站点类型影响研究边界，**筛选旧预测解决不了训练问题**。
- **先做（零训练）**：确定纳入规则（例如仅 ST，或 ST + 明确的受河流影响类型），输出站点清单与数量对比，记录被排除的站点及其 DOC 标签量。
- **最小实验**：ST 核心版本重新构图与划分后，跑 H1/H2/H2X × 8 key mask × 3 训练种子 = 72 次运行（先 3 种子而非 5，确认方向后再补）。
- **要求**：新划分必须保存为新的 mask 文件，**不得覆盖** `experiments/masks/` 现有文件。

## 3. B2：同协议对照，分离三类贡献

- **目标**：分离「输入信息」「编码器」「消息传递」三类贡献，并建立**有效无图对照**。
- **最小实验矩阵**（同一数据版本、同一划分、同一早停规则）：

| 对照 | 分离的问题 |
|---|---|
| H2 / H2E / H2X（同协议） | 生态信息与编码器各自的贡献 |
| H2X + 生态 RF / 生态 MLP | 增益是否只来自输入信息，而非图消息传递 |
| 有效无图版本（去掉边但保留特征与训练预算） | 图结构本身是否必要 |
| transport 路径的消融（改的是变体还是真的关掉了门控） | 门控是否真的生效 |

- **规模**：4 组 × 3 训练种子 × 8 key mask ≈ 96 次运行。
- **要求**：transport 路径**不能只改 variants 就假设消融生效**，需要断言门控权重确实参与前向计算。

## 4. B3：r40/r60 多种子与空间分块、外流域评估

- **问题**：key mask 均值不能替代这些证据。目前 r40/r60 只有历史单次结果。
- **最小实验**：`e1_r40_*`、`e1_r60_*` 各 3 种子 × H1/H2/H2X = 18 次运行；空间分块评估与一个外流域留出集另计。
- **要求**：外流域评估需先确认该流域的站点数、标签量与图连通性，否则先做可行性核对（零训练）。

## 5. B4：H2X + 历史输入基线，再比较 H3/GRU

- **先决**：明确**合法历史**的定义（哪些过去时刻的观测可用）、时间窗口长度与**无泄漏协议**（历史 DOC 在 test 期是否可见、以何种延迟可见）。
- **最小实验**：先做 H2X + 历史输入基线（3 种子 × 8 key mask = 24 次运行），再决定是否上 H3/GRU。
- **要求**：**不预设** GRU 能恢复不可观测的极端事件。本轮 A3 已证明极端值贡献了大部分误差（top 1% 占 74%），因此任何「恢复极端事件」的主张都需要专门的极端值评估协议，而非整体 MAE。

## 6. 五训练种子逐样本预测（可选，成本最高）

- **现状**：120 个 (模型, 种子, mask) 组合只有指标，无逐样本预测。这是五种子集成、残差地图、逐站区间**无法开展**的唯一原因。
- **成本**：H1/H2/H2X × 5 种子 × 8 key mask = **120 次训练**。
- **建议**：先做 B2 的小规模同协议对照（96 次），确认哪些配置值得补齐五种子预测，避免先花 120 次训练去补一批可能被 B1/B2 取代的配置。

## 7. 预算估算口径

进入下一阶段前按以下三项估算，**不使用完整训练计时**：

1. 现有日志中可提取的单次运行耗时（若有）；
2. 单独安排的最小试跑（例如 1 个 mask、1 个种子），只用于估时；
3. 参数规模 × 数据规模的比例外推，用于量级核对。

三项需交叉验证；仅凭外推不得作为承诺工期的依据。
